# 界面与交互

适用：新增或修改页面、组件、导航、表单、动画、响应式布局和视觉风格。文案的写法见 [文案与表达](copywriting.md)。

下面是没有项目规范时的默认做法。项目有自己的设计规范时，以规范为准。

## 设计系统

- 颜色、字体、间距、圆角集中成设计变量，页面只通过项目自己的组件层使用，换风格只改一处。
- 页面只用设计变量里的档位，不写零散的间距数值，也不硬编码颜色。状态色（成功、警告、危险）从语义变量取。
- 缺组件时，先在组件层补上，再在页面里使用。不要在页面里临时拼底层组件库的控件。
- 项目还没有设计系统时，选一套基础组件库并保持一致，少量公共样式集中管理，不为一个页面自建组件体系。
- 全站只用一套图标库，描边粗细一致。图标库里没有的，按同样的规格补画，不混用别的图标集。
- 品牌色、主题、断点由产品决定，不从其他项目照搬数值。
- 用检查脚本守住边界，比如禁止页面直接引用底层组件库，做法见 [依赖与迁移](dependencies-and-migrations.md) 的棘轮检查。

## 去掉 AI 味

AI 生成的界面有一些常见的模板痕迹。没有产品或设计上的理由时，不要使用：

- 默认的紫蓝渐变、霓虹光晕、毛玻璃、大面积阴影和过大的圆角。
- 标题和按钮里的 emoji，或者用 emoji 代替图标。
- 「图标 + 标题 + 一句描述」的卡片阵列反复出现；所有内容都装进卡片、全部居中对齐。
- 编造的数据、用户评价、合作方 Logo，以及「10000+ 用户信赖」这类占位信息。
- 空泛的大标题（「开启……新时代」「释放……的力量」）和没有信息量的副标题。
- 没有目的的入场动画、悬停放大和闪烁徽标。
- 用大片留白撑版面。工具类界面要紧凑，分区用细分隔线或小间距。

应该这样做：

- 从真实内容和用户的主要任务出发排版。信息层级靠字号、字重、间距和对齐表达，不靠装饰。
- 每个元素都要帮用户区分内容或做出决定。区分不了内容的缩略图、头像和装饰图标，不放。
- 同一条信息只出现一次。比如日期已经在分组标题里，卡片里就不再重复。
- 颜色要有含义：强调色只用于主要操作和关键状态。
- 用接近真实的数据检查布局，包括很长的名字、空值和很大的数字。

## 操作的摆放

- 每个区域最多一个主按钮，次要操作在视觉上让位。
- 顶栏右侧最多放一个带文字的操作，不堆一排纯图标按钮，用户分不清它们的功能。
- 多选后的批量操作放在底部操作栏（图标加文字），横屏时可以放到侧边，单手够得到。
- 删除等破坏性操作不放在每个列表项上，走多选后的批量操作，确认框写清删除的范围。
- 列表行整行可点，行内的开关、单选圆点只用来展示状态，不要只有小控件能点。
- 互斥选项不超过 5 个时用分段控件，更多时用列表或对话框。带图标和说明的选项不要放进下拉菜单。
- 确认对话框只留给真正有风险的操作。可以撤销的轻操作，提供撤销而不是弹确认。

## 布局

- 按容器实际可用的宽高布局，考虑分屏、弹窗、侧栏和弹出的键盘，不只看屏幕方向或设备类型。
- 内容超出时允许滚动，主要操作和正在输入的字段保持可见。检查窄屏、矮窗口、大字号和超长文本，不要靠裁切隐藏问题。
- 加载中、空数据、出错、内容很多，这四种状态都要设计并检查。
- 会变化的数字（计时、计数、金额、进度）和表格里的数字用等宽数字，比如 CSS 的 `font-variant-numeric: tabular-nums`，否则数字跳动时左右抖。自己绘制的文字（画布、导出图片）也要带上。
- 会切换文字的按钮（「全选」和「取消全选」）按最长的文字预留宽度，切换时旁边的控件不跳动。

## 状态与输入

- 界面只负责展示，业务判断放在业务层，见 [架构与状态](architecture-and-state.md)。禁用按钮不能代替服务端校验。
- 提交时给出反馈，并防止重复提交。成功、失败、取消和结果未知要分别呈现。
- 用户正在输入时不要强行修正输入值，完整校验通过后再提交。
- 布局形态切换时（比如弹窗随窗口大小变化），内容在组件树中的位置保持不变。否则表单会被清空，输入框失焦、键盘收起，又触发形态切换，来回抖动。
- 可滚动页面里的滑块和拖动控件要区分方向：横向移动超过阈值才开始拖动，纵向滑动交给页面滚动，防止用户滚动时误改数值。
- 回调和手势处理要读取当前状态，留意闭包里捕获的旧值。

## 导航与动画

- 返回操作的处理顺序保持一致：先退出多选、关闭弹层，再退出页面。
- 动画进行中，离场页面和遮罩下的元素不响应点击。
- 动画可能被连续点击或反向操作打断，中间状态也要正确。

## 可访问性

- 图标按钮要有可读的名称。状态不能只靠颜色区分。对比度、点击区域和焦点顺序符合平台规范。
- 主要任务能只用键盘或读屏软件完成。快捷键不能抢占输入框和系统快捷键。
- 权限被拒或功能不可用时，告诉用户下一步可以做什么。

## 验证

- 截图只能证明外观。交互、焦点和可访问性要实际操作一遍，证据要求见 [测试与验证](testing.md)。
- 页面多的项目，加一个冒烟测试：在几种典型尺寸（桌面、平板横竖屏、手机横竖屏）下渲染各个页面，检查布局溢出和报错。
