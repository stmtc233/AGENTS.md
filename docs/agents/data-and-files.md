# 数据与文件

适用：修改数据模型、数据库、迁移、缓存、文件读写、导入导出或中断恢复。

沿用项目已有的数据访问方式，不为统一风格更换存储方案。

## 模型

- 每类数据都要清楚：权威来源在哪、由谁写入、保留多久、何时删除、能否重建。
- 用户的原始数据和派生数据（缩略图、转码文件、索引、缓存）分开管理。生成派生文件时，原始文件永远不替换。
- 会持续增长的结构化数据存进数据库，不要整块序列化后存进键值存储，否则改一条就要重写全部。
- 关联数据用稳定的 ID，不靠显示名称、列表位置或文件路径判断是否同一个对象。
- 读取时校验必填字段和取值范围。读取失败要报出来，不能当作空数据再写回去。
- 使用项目现有的连接和事务管理，不另起一套。

## 格式与迁移

- 持久化格式写明字段含义、单位、默认值和版本号。不要用代码里当前的默认值去解释旧数据。
- 改格式前检查已有数据、导出文件和外部读取方，按项目的兼容策略迁移，或明确拒绝读取。
- 迁移走项目已有的迁移机制，中断后能安全重跑。不要用删表重建绕过迁移。
- 依赖字段名、反射或代码生成的序列化，要在发布构建（压缩、混淆、裁剪之后）里实测读写。
- 迁移和数据清理分开做。代码不再使用某个字段，不代表里面的数据可以删。

## 写入

- 一次业务修改涉及多条记录时用事务，失败时不留下半套结果。
- 提交成功后再通知依赖方。
- 后台任务写入前读取最新记录，只改自己负责的字段，必要时加版本条件。
- 导入、重试和批处理要幂等，重复执行不能产生重复记录。
- 文件和数据库无法放进同一个事务。设计好步骤顺序和失败时的补偿，不要假设两边会同时成功。
- 删除前检查引用关系和正在运行的任务，避免删除后又被旧任务重新创建。

## 文件

- 大文件流式处理，不要整个读进内存。
- 新文件先写到临时位置，写完并校验后再替换到正式位置。导出文件写完并成功关闭才算完成。
- 目标文件已存在时，按明确的策略拒绝、改名或覆盖，不能让底层操作静默覆盖用户文件。
- 处理外部文件（上传、导入、解压）时：规范化路径并确认它仍在允许的目录内；限制条目数和解压后的大小；按内容而不是扩展名判断格式。
- 成功、失败、取消都要清理临时文件。

## 缓存

- 缓存键包含对象身份和所有影响结果的参数。算法或格式变化时更新缓存版本。
- 并发生成同一份缓存时防止读到半成品：复用进行中的任务，或写临时文件后原子替换。
- 清理孤立文件时，排除正在使用和等待恢复的文件。源数据删除后，清理它的派生文件。

## 验证重点

按风险选择：迁移重跑、重复导入、重名、损坏的输入、中途中断、并发修改。用临时数据测试；必须动真实数据时先备份。
