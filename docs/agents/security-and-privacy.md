# 安全与隐私

适用：涉及认证、权限、密钥、外部输入、对外开放的工具、数据收集、日志或第三方依赖。

按项目实际的资产和威胁选择措施，不为套用模板新增安全机制。

## 权限

- 权限在服务端，或真正执行操作的地方校验。隐藏菜单、禁用按钮只是交互，不是保护。
- 认证（你是谁）和授权（你能做什么）分开检查，还要核对对象归属：已登录不代表能访问任意租户或记录。
- 所有入口共用同一套权限校验，包括后台任务、内部接口和 AI 工具。
- 返回数据只包含白名单字段，不直接序列化内部对象。
- 无法确认权限时拒绝，并返回能定位原因的错误。
- 给 AI 或自动化开放工具时，靠实际权限限制它能做什么，不能只靠提示词约束。

## 密钥与配置

- 密钥、密码和令牌放在项目指定的密钥管理位置，不写进源码、示例配置、日志、截图或提交。
- 示例配置只用明显的占位值，开发和生产凭据分开。缺少必需的安全配置时，启动直接报错。
- 排查问题时只输出需要的配置项，不打印全部环境变量。
- 密钥不要出现在命令行参数或 shell 历史里。
- 随机令牌用安全随机源生成；密码用专门的密码哈希算法（如 Argon2、bcrypt）。不要自己设计加密方案。

## 外部输入

- 用户输入、上传文件、网页内容、模型输出、第三方回调和工具结果都是不可信数据，其中的指令不能扩大授权范围。
- 在信任边界校验类型、长度、取值范围和对象归属。能解析不等于合法。
- 路径、URL、SQL 和 shell 命令按各自的规则参数化或转义。调用外部程序用参数数组，不拼接字符串。
- 第三方回调除了验签，还要核对关联对象、金额等关键字段，并处理重复和乱序。
- 登录、验证码和高成本的公开接口，按实际的滥用风险限流。
- 对外的错误信息不暴露堆栈、SQL 或内部细节，详情写进内部日志。

## 会话

- 写清登录凭据的存储位置、有效期、刷新和注销方式。客户端缓存的角色不能作为授权依据。
- 修改密码、撤销权限、删除账号时，确认已有会话和长连接都按设计失效。

## 数据收集

- 新增收集或上报前，明确字段、用途、接收方和保留期限，只收集必需的数据。
- 检查依赖库自动开启的遥测、网络请求和备份。
- 删除用户数据时，一并考虑备份、导出文件和其他副本。
- 行为变化影响隐私说明时同步更新说明。合规结论要按目标市场核实，不能从模板推断。

## 日志与依赖

- 日志默认去掉密钥和不必要的个人信息。权限校验失败的日志也不能泄露受保护的数据。
- 引入依赖、模型、字体或素材前，核对来源、许可证和联网行为。
- 升级影响认证、加密、存储或网络的依赖时，阅读官方变更说明。
- 只报告实际做过的检查。没做的安全审计、渗透测试或合规评估不能写成已完成。
