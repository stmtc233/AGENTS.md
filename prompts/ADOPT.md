# 接入提示词

在目标项目里打开 AI，把分隔线以下的内容发给它。如果规范文件还没复制进项目，把第一行的 `<规范路径>` 换成本仓库在你电脑上的位置；已经复制过的，删掉这一行。

---

规范来源：`<规范路径>`

请把这套 AI 协作规范接入当前项目。

1. 先读项目的 README、已有的 AI 规则文件（`AGENTS.md`、`CLAUDE.md` 等）、构建和测试配置，并检查 Git 工作区。已有内容和未提交的改动都要保留。
2. 只改文档。不改业务代码，不装依赖，不建服务。
3. 项目里缺少的规范文件从规范来源复制：`AGENTS.md`、`CLAUDE.md`、`docs/agents/`，以及 `templates/PROJECT_CONTEXT.md`（放到项目根目录）。
4. 项目已有 `AGENTS.md` 或 `CLAUDE.md` 时合并，不要覆盖：
   - 根 `AGENTS.md` 采用规范版本；
   - 原文件里项目特有的内容（命令、术语、约定、注意事项）移到 `PROJECT_CONTEXT.md` 或对应模块的 `AGENTS.md`；
   - 原有规则与规范意思相同的可以去掉；不同或冲突的，保留到 `PROJECT_CONTEXT.md` 的「约定」里，以项目规则为准；
   - `CLAUDE.md` 保留 Claude Code 专用的内容，通用部分改为 `@AGENTS.md` 引用。
5. 根据实际代码填写 `PROJECT_CONTEXT.md`。只写核实过的事实；命令注明工作目录，没实际跑通的标「未验证」；查不到的写「待确认」。项目已有的设计文档、细则里改错会出问题的规则，整理成「关键约束」（每条一句，链接原文），并在「改动路由」里写明改哪些目录前要先读哪份文档。
6. 删除与本项目无关的专题，例如没有界面就删 `ui-and-interaction.md`，并删掉路由表里对应的行。保留下来的通用专题正文不改写；项目在这些主题上已有的约定，写进各专题末尾的「本项目补充」。
7. 项目原有的设计文档或细则，当作项目专题，留在原位置，登记到「改动路由」。不移动，也不为套格式改写内容。
8. 模块较多时，在主要模块目录下建局部 `AGENTS.md`，只写该模块的入口、约定和注意事项。
9. 检查链接、路由表、残留的占位符、个人电脑上的绝对路径和敏感信息。

完成后告诉我：新增和修改了哪些文件，删了哪些专题及原因，原有内容挪到了哪里，哪些事实核实过，还有哪些需要我确认。不要提交或推送。
